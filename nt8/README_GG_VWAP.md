# GG VWAP strategies — 2026-11-02

New versions of the current GG standalone and GG routed MaxGreenRun scripts:

- `GG_m_w_r_stoplimits_and_tplimit_InstanceID_WindowRR_Offsets_SafeExits_MaxGreenRun_VWAP.cs`
- `GG_m_w_r_stoplimits_and_tplimit_InstanceID_WindowRR_Offsets_SafeExits_Routed_MaxGreenRun_VWAP.cs`

Their strategy names are `GGLongTimeWinStopLimitTPlimitGAPWindowRROffsetsSafeExitsGreenRunVWAP`
and `GGLongTimeWinStopLimitTPlimitGAPWindowRROffsetsSafeExitsRoutedGreenRunVWAP`.

Install the wanted file(s) in your NinjaTrader user-data folder's
`bin\Custom\Strategies`, then compile in NinjaScript Editor (F5). Both use the
existing `RTLSessionVWAP.cs` in `bin\Custom\Indicators`: **install just one copy**
shared with the RR variants. The routed GG strategy requires `PropRouterGG.cs` in
`bin\Custom\AddOns`, just like its original. It uses GG's own router and signal
names, not the RR router. Transfer your original GG quantity, Instance ID, window
R:R and routing settings to the new strategy type. R:R defaults remain zero.

Use **standard M30 bars, Calculate.OnBarClose, CME ETH**, and several days of
history. The default gate rejects a **green** entry signal only when its close is
strictly below **VWAP − A20**. Equality allows entry. This is the same filter as
the RR VWAP variants, applied to GG's green candles. VWAP uses one-minute HLC3
prices weighted by volume; A20 is the simple average of 20 true ranges spanning
sessions, requiring 21 primary bars. Unknown values allow entries.

The blue plot is session VWAP and the orange plot is the cutoff. Defaults:
`UseVwapGate=true`, `VwapFarBelowZ=-1`, `VwapAnchorMinute=0`,
`VwapSessionTimeZoneId="Central Standard Time"`, `VwapSessionShiftMinutes=480`,
`ShowVwapIndicator=true`, `LogVwapDecisions=false`. The session date uses Chicago
DST plus 8 hours, matching the existing RR implementation. To filter directly at
the blue VWAP line instead, set **Far-below Z=0**.

VWAP only filters new entries. A rejected green signal cancels the previous
pending entry through the existing cancellation flow. Red/doji bars preserve
pending entries as in the original GG scripts. Stops, targets, entry expiry,
timeout handling and router ownership callbacks retain the original behavior.
Use identical filter settings across seats of a GG book; enabled settings are
included in the book's configuration check. Gate-off keeps the original GG key.

The indicator warms on historical data; the strategies retain their original
realtime-only order submission. Use Sim or Market Replay to check execution.
Enable decision logging to inspect the filter in NinjaScript Output. An incomplete
initial session or missing final minute is unknown and allows an entry. Full ETH
data is required for overnight VWAP; an RTH chart supplies an RTH-only VWAP.

Validation: both new GG strategies compile alongside the original GG and RR
strategies, both routers, the RR VWAP variants and shared indicator against the
installed NT8 assemblies, with zero errors. 37 assertions exercise the actual GG
entry-gate and router-key methods; 47 shared calculation assertions pass. Sim
